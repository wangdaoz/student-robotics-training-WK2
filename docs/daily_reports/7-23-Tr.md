  ## How I investigated
     Q1, I asked claude code via chat form: "After I change contents in the status_publisher.py, should I rebuild and resource again?"
        
        then, it answered me:
          Any time you edit the file's contents (not just add an entry point), for a Python ament_python package you technically don't need a full colcon build in the strict sense, because ament_python packages are often installed via symlink or a copied .py file — but this depends on how you built it:
                
           ● If you built with <colcon build --symlink-install>: your install/ directory contains symlinks back to your source files. Editing status_publisher.py in src/ is reflected immediately — no rebuild needed. I still need to <source install/setup.bash> once per new terminal but not again after every edit.

           ● If you built with plain <colcon build> (no symlink flag): Python files get copied into install/. Editing the source file in src/ does nothing until you rebuild — <ros2 run> will keep executing the old copied version.

        So I recalled, I had build with plain <colcon build> so I should rebuild the package.
        Claude code told me another relevant command: <colcon build --packages-select student_robotics>, thus I inputted commands:
        <colcon build --packages-select student_robotics>, <source install/setup.bash>, <ros2 run student_robotics status_publisher>; The new version of publisher file was executed successfully.

      Q2, I asked the Claude code "You said that "self.subscription line: this isn't functional, it's just there to avoid a linter/IDE warning about an "unused" variable, since the subscription object needs to stay alive as an attribute on self for the callback to keep firing." I don'y understand why <self.subscription> could avoid a linter/IDE warning about an "unused" variable?"

       The Claude code explained " a no-op: it just evaluates the attribute and throws the result away.
         it functions more like an inline comment: a visual signal to a human reader (or to some IDEs that flag "attribute assigned
          but never read elsewhere in the file") saying "yes, this attribute is intentionally kept around even though I never call 
          self.subscription again."

          Then I understood that this line is performed like a flag that implicates that the attribute assigned before is intentionally kept around here.

      Q3, I also asked Claude code, the clauded code taught me to open three terminals: the first is running publisher node, the second is running subscriber node and the remind one is used to input commands: <ros2 topic list>, <ros2 topic echo /robot_status>, and <ros2 topic hz /robot_status> separately.
        The details are provided in "docs/pub_sub_setup.md"
